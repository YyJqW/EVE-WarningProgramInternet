# EVE 预警系统

- **注意在EVE晨曦可能违反用户协议造成的任何损失由使用者自行承担**

基于 .NET 8.0 的 EVE Online 游戏智能预警系统，通过图像识别和实时网络通信，帮助玩家监控游戏状态并及时预警。

## 功能特性

### 客户端
- **屏幕实时监控**：3秒倒计时抓取游戏窗口截图
- **智能图像识别**：
  - 使用 Emgu.CV (OpenCV) 进行模板匹配
  - 5种预警色块检测（宣战、对战、糟糕、不良、白名）
  - 灰度匹配 + 颜色验证的双重识别策略
- **OCR 文字识别**：自动识别玩家角色名（PaddleOCRSharp）
- **实时网络通信**：
  - TCP Socket 连接服务器
  - 预警数据实时推送
  - 自动重连机制（最多5次，递增延迟）
  - 心跳保活（30秒间隔）
  - 预警去重，避免重复推送
- **灵活的 UI 操作**：
  - 拖动滑动条裁切检测区域
  - 框选裁切工具可视化选择区域
  - 实时日志记录
  - 预警声音提示
  - 可配置更新频率
- **聊天日志预警（预警频道）**：
  - 读取 EVE 客户端 `Chatlogs` 目录中的聊天日志
  - 自动识别中英文星系名（离线数据，不依赖 ESI）
  - 按「所在星系 + 警报跳数」过滤，只对范围内的星系预警
  - 只监控用户勾选的频道，避免本地/交易频道误报
  - 本地色块预警与频道预警**各自**支持自定义音频、试听和音量（0–100）
  - 警报可循环播放，循环时长可配置；主界面「停止警报」可立即停止
  - 未选择音频时使用内置提示音（同样支持音量与循环）
  - 支持 WAV / MP3 / AIFF / WMA / M4A 等常见格式
  - 启动时跳过历史消息，按星系冷却去重，避免刷屏
  - 连接服务器时把频道预警以 `type=intel` 转发给服务器广播
  - 本地色块预警也使用同一套自定义音频（默认开启声音）

### 服务器端
- **多客户端管理**：支持多个客户端同时连接
- **实时消息广播**：接收客户端产出的预警并广播给其他在线客户端
- **两类预警统一转发**：
  - 色块预警（`type=alert`，红/白等图标）
  - 预警频道消息（`type=intel`，来自生产端客户端的聊天日志判定）
- **在线用户监控**：显示用户名、星系、连接时间、最后心跳
- **心跳检测**：自动清理超时客户端（30秒间隔，3次超时判定）
- **无人值守**：支持 `--autostart` 启动参数，日志写入 `%APPDATA%\EVE预警\server.log`
- **优雅退出**：服务器关闭时断开所有客户端

## 快速开始

### 环境要求

- Windows 10/11
- .NET 8.0 SDK
- Visual Studio 2022（推荐）

### 编译运行

1. **克隆项目**
   ```bash
   git clone <repository-url>
   cd EVE预警
   ```

2. **打开解决方案**
   ```
   使用 Visual Studio 打开 EVE预警.sln
   ```

3. **还原依赖**
   ```bash
   dotnet restore
   ```

4. **编译项目**
   ```bash
   dotnet build
   ```

5. **运行**
   - 先启动 **EVE预警服务器** 项目
   - 再启动 **EVE预警** 客户端项目

### 生成可直接运行的版本（推荐）

目标电脑无需安装 .NET 8：

```bash
dotnet publish "EVE预警/EVE预警.csproj" -c Release -r win-x64 --self-contained true
```

产物位于 `EVE预警/bin/Release/net8.0-windows/win-x64/publish/`，
双击其中的 `EVE预警.exe` 即可运行。**整个 publish 目录需要一起拷贝**，
不能只复制 exe。

服务器同理：

```bash
dotnet publish "EVE预警服务器/EVE预警服务器.csproj" -c Release -r win-x64 --self-contained true
```

### 使用流程

1. **启动服务器**
   - 运行服务器程序
   - 点击"启动服务器"按钮，默认监听 2424 端口
   - 无人值守可用 `EVE预警服务器.exe --autostart` 自动开始监听

2. **配置客户端**
   - 输入服务器 IP 地址
   - 输入当前星系名称

3. **抓取游戏窗口**
   - 切换到 EVE 游戏窗口
   - 点击"抓取窗口"按钮，3秒后自动截图

4. **选择检测区域**
   - 使用滑动条调整区域，或点击"框选裁切"可视化选择
   - 确保区域覆盖预警图标显示位置

5. **开始检测**
   - 点击"开始检测"按钮
   - 系统会定期检测并发送预警数据

6. **配置聊天日志预警（可选）**
   - 点击主界面下方"预警与音频设置"
   - 日志目录会自动检测（通常为 `文档\EVE\logs\Chatlogs`），也可手动选择
   - 填写所在星系（支持中英文名，带自动补全）
   - 设置警报跳数（0 表示只对所在星系本身告警）
   - 在频道列表中勾选要监控的预警频道（可点"刷新频道"重新扫描）
   - **本地色块预警音频**：选择文件、试听、调整音量（留空使用系统提示音）
   - **频道预警音频**：同样支持自定义文件、试听、音量（本地频道与服务器广播共用）
   - 音量对自定义音频和内置提示音都生效
   - 「警报循环时长」设置循环秒数（0 = 只播一次）；循环期间点主界面「停止警报」可立即停止
   - 点击"模拟一条预警消息"可不再进入游戏验证整条链路
   - 确定后立即生效，设置会保存到 `%APPDATA%\EVE预警\config.json`

### 预警频道的工作方式

- 生产端客户端读取本机聊天日志，**运行时不访问任何网络接口**。
- 启动时会跳过已有历史消息，只对启动之后的新消息告警，避免刷屏。
- 同一条消息在多个角色的日志里重复出现时只处理一次；同一个星系在冷却时间内只告警一次。
- 一条消息提到多个范围内星系时，按最近的那个星系告警一次。
- 连接服务器时，生产端会把命中的频道预警以 `type=intel` 发给服务器，由服务器广播给其他客户端（不回报给发送者）。
- 消费端收到 `type=intel` 或色块广播时，写入预警日志并播放告警音频。
- 本地色块预警（红/白等）同样会发送给服务器，并优先使用设置里的自定义音频。

### VM 小号作为生产端（推荐部署）

```
VM：EVE 客户端（小号） + EVE预警客户端（生产者） + EVE预警服务器（广播）
                         │ TCP 2424
宿主机：EVE 客户端（大号） + EVE预警客户端（消费者，响铃）
```

1. VM 里登录预警小号，加入情报频道。
2. VM 里启动服务器（无人值守加 `--autostart`）：
   ```powershell
   EVE预警服务器.exe --autostart
   ```
3. VM 里启动 `EVE预警.exe`：
   - 服务器 IP 填 `127.0.0.1`（同一台 VM），连接服务器
   - 「预警与音频设置」里配置日志目录、所在星系、跳数、监控频道、音频
   - 如需红/白色块预警：抓取 VM 内的 EVE 窗口、框选区域、开始检测
4. 宿主机启动 `EVE预警.exe`，服务器 IP 填 VM 的 IP，连接服务器。
5. 宿主机客户端收到两类广播都会写日志并响铃；它不需要配置聊天日志。

> 服务器不需要声卡，也不读取聊天日志；它只负责转发。音频只在客户端播放。

## 网络协议

### 消息格式

所有消息使用 JSON 格式，以换行符 `\n` 分隔。

**注册消息**
```json
{
  "type": "register",
  "username": "玩家名称",
  "galaxy": "星系名称"
}
```

**心跳消息**
```json
{
  "type": "heartbeat"
}
```

**预警消息**
```json
{
  "type": "alert",
  "galaxy": "星系名称",
  "alerts": ["RedStar:2", "OrangeCross:1"]
}
```

**广播消息（服务器→客户端）**
```json
{
  "galaxy": "星系名称",
  "message": "宣战:2,对战:1"
}
```

**预警频道消息（客户端→服务器→其他客户端，`type=intel`）**
```json
{
  "type": "intel",
  "galaxy": "皮尔米特",
  "system": "皮尔米特",
  "jumps": 1,
  "channel": "TestIntel",
  "author": "AltPilot",
  "message": "hostiles in Perimeter",
  "time": "2026-10-24T12:00:01.0000000Z"
}
```

客户端收到后写入「预警日志」并播放告警音频；`jumps` 为与服务器配置的所在星系之间的跳数。

## 开发说明

### 添加新的预警类型

1. 在 `ImageProcessor.cs` 的 `AlertType` 枚举中添加新类型
2. 添加对应的模板图片（如 `6.png`）
3. 在 `Main.cs` 的 `alertTypeMap` 中添加中文映射
4. 在 `GetAlertMessage` 方法中添加对应的提示信息

### 自定义模板匹配阈值

在 `ImageProcessor.cs` 第 216 行修改匹配阈值：
```csharp
if (maxVal >= 0.85)  // 修改此值调整匹配灵敏度
```

### 更新离线星系数据

`EVE预警.Shared/Data/map-data.json` 由开发期工具生成，客户端运行时不会访问 ESI / SDE：

```bash
# 首次会下载约 112 MB 的官方 SDE 到临时目录
dotnet run --project tools/GenerateMapData -- --out "EVE预警.Shared/Data/map-data.json"

# 已有 sde.zip 时可指定本地文件；--no-zh 表示不拉取中文名
dotnet run --project tools/GenerateMapData -- --sde "C:\path\to\sde.zip"
```

生成工具会随机抽取 20 对星系，用 ESI 线路校验本地 BFS 跳数，不一致则中止。
生成后重新编译客户端即可。该工具仅用于开发期，目标框架为 `net10.0`
（若本机只有 .NET 8 SDK，请把 `tools/GenerateMapData/GenerateMapData.csproj`
中的 `TargetFramework` 改为 `net8.0`）。中文名缓存保存在
`tools/GenerateMapData/zh-cache.json`，重跑时可断点续传；在没有 ESI 访问的
环境中，可复用该缓存只重建跳跃图。

### 修正个别星系的名称映射

若中国服务器的译名或新增星系与内置数据不一致，可创建
`%APPDATA%\EVE预警\system-aliases.json`（值可以是目标名称或星系 ID）：

```json
{
  "吉他二号": "Jita",
  "新星系": 30000142
}
```

也可以用同名文件覆盖整个地图数据：`%APPDATA%\EVE预警\map-data.json`
（格式与 `EVE预警.Shared/Data/map-data.json` 相同，存在时优先使用）。

## 注意事项

- 确保 EVE 游戏窗口未被遮挡
- 检测区域应仅包含预警图标区域
- 服务器端口默认为 2424，可在服务器端修改
- 客户端自动重连最多尝试 5 次
- **地图数据说明**：内置跳跃图来自 Tranquility 官方 SDE（2025-07-07）。
  中国服务器（Serenity）与 Tranquility 的星系集合可能存在差异，未覆盖的星系
  可用上面的别名文件补充；这类差异不会影响其余星系的跳数计算。
- **聊天日志格式**：解析器兼容 UTF-16LE / UTF-8，并允许每行带或不带 BOM。
  若中国服务器客户端的日志格式不同，可在设置窗口的状态区查看实际识别结果，
  并据实调整 `ChatLog/ChatLogParser.cs`。
- 本功能只读取本地日志，ESI 不可用的环境下同样可以正常工作。
